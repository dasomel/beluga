# 특권 접근 인벤토리 및 관리 경계 (Privileged Access Inventory and Administrative Boundaries)

[English](privileged-access-inventory.md) | 한국어

이 문서는 [이슈 #44](https://github.com/dasomel/beluga/issues/44)의 인수 기준 1번("Privileged access paths are inventoried — 특권 접근 경로 인벤토리화")을 충족하기 위한 Beluga 데이터 플랫폼의 특권 접근 인벤토리를 정의한다. 기준 2~5번(특권 작업 구조화 감사 로그 생성, 보호 데이터 경로 DB 접근 로깅 정책 수립 및 적용, 보관/검토 규칙 정의, 정기 감사 보고서 생성) 및 일반적인 특권 접근 관리(PAM) 통제 항목(MFA, 세션 레코딩, 사전 승인 워크플로)은 후속 구현 단계의 대상이며 본 인벤토리 기준선에서는 완료로 주장하지 않는다.

---

## 2. 자격증명 경계 및 로깅 통제 현황

### A. 비밀값 미커밋 원칙 및 런타임 생성
[SECURITY-ko.md](../SECURITY-ko.md) 및 [docs/configuration-sources-ko.md](configuration-sources-ko.md)에 따라 평문 암호나 API 토큰은 Git에 일절 저장되지 않는다:
- **루트 자격증명**: [`scripts/gitops/01-argocd-bootstrap.sh`](../scripts/gitops/01-argocd-bootstrap.sh)가 `openssl rand -hex`로 난수를 생성하여 `platform-system` 네임스페이스의 `beluga-credentials` Secret에 저장한다.
- **네임스페이스 격리 파생 Secret**: `01-argocd-bootstrap.sh`는 각 워크로드 네임스페이스에 필요한 최소 자격증명만 비관리(unmanaged) Secret(`postgres-admin-credential`, `keycloak-admin-credential`, `keycloak-db-credential`, `ldap-admin-credential`, `ldap-reader-credential`, `apisix-admin-credential`, `superset-credential`, `seaweedfs-s3-credentials`, `postgres-backup-s3-credential`)으로 복제한다.
- **오퍼레이터 자격증명**: CloudNativePG는 런타임에 `postgres-main-superuser`와 `postgres-main-app`을 생성하며, 이들의 순환은 이 저장소에서 확립되지 않았다. cert-manager는 `*-tls-secret` 인증서를 발급하고 각 Certificate의 `renewBefore`에 따라 만료 전에 갱신한다(`scripts/ci/check-certificate-inventory.py`가 강제).

### B. 컴포넌트별 감사 로깅 수립 현황
저장소 검증 결과 현재 매니페스트에는 전용 보안 감사 로깅 정책이 대부분 구성되어 있지 않다:
1. **쿠버네티스 API**: [`scripts/cluster/02-k8s-init.sh:27-31`](../scripts/cluster/02-k8s-init.sh#L27-L31)의 k3s 기동 옵션에 `--audit-policy-file` 또는 `--audit-log-path`가 지정되어 있지 않다.
2. **PostgreSQL**: [`gitops/charts/beluga-data/templates/02-cnpg.yaml:47-51`](../gitops/charts/beluga-data/templates/02-cnpg.yaml#L47-L51)의 `postgresql.parameters`에 `pgaudit` 확장이나 연결/문장 감사 플래그(`log_connections`, `log_disconnections`, `log_statement`)가 선언되어 있지 않다.
3. **OpenLDAP**: [`gitops/charts/beluga-platform/templates/openldap.yaml:120-160`](../gitops/charts/beluga-platform/templates/openldap.yaml#L120-L160)의 slapd 데몬에 `slapo-accesslog` 오버레이가 설정되어 있지 않다.
4. **Keycloak 및 ArgoCD**: 관리자 감사 로그 대상지 또는 외부 감사 이벤트 전달은 이 저장소에 수립되어 있지 않다.
5. **APISIX**: HTTP 요청 접근 로그는 `/dev/stdout`으로 출력되도록 구성되어 있으나([`gitops/charts/beluga-platform/templates/apisix-gateway.yaml:59`](../gitops/charts/beluga-platform/templates/apisix-gateway.yaml#L59)), 관리자 변경 감사 로깅은 이 저장소에 수립되어 있지 않다.
6. **Superset**: 전용 관리자 감사 로깅 또는 보안 모니터링 연동은 이 저장소에 수립되어 있지 않다.
